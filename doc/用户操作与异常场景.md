# 用户操作与异常场景

> **用途**：本文档从用户视角列出插件的全部可预期行为与异常处理，供开发者在修改代码时对照错误处理逻辑，或作为手动测试清单逐项验证插件是否有 bug。
>
> **维护约定**：改动 `public/preload/*` 或 `src/**` 后若行为发生变化，必须同步更新本文档；反之，修改前应先读本文档确认"哪些行为是刻意设计的"，不要误删防护逻辑。
>
> **代码位置约定**：`preload/xxx` 指 `public/preload/xxx`；`src/xxx` 为渲染层。所有写操作最终收敛到 preload，前端只负责展示与排队提交。

| 1.7 | 渲染层出现意外异常 | 弹出"界面发生错误：..."提示，不白屏（最后一道兜底） | `src/main.js` 的 `app.config.errorHandler` | 代码走查 |

| 2.2.11 | 仓库目录本身无法读取 | 报错"无法读取仓库目录 ...。为防止误删，本次不会清理缺失项。"，保留上次缓存 | 同上 | 代码走查 |
| 2.2.12 | 单个 SKILL.md 超过 2 MB | 拒绝读取并报错 | 同上（MAX_SKILL_FILE_BYTES） | 造一个超大文件 |

### 2.3 扫描后的收敛与防护

| # | 场景 | 插件预期行为 | 代码位置 | 测试要点 |
|---|---|---|---|---|
| 2.3.1 | 扫描成功且有结果 | 更新缓存；清理失效引用；逐个 Agent 同步链接；无错误时提示"已重新扫描 Skills" | `preload/api.js:refreshInternal` | 常规刷新 |
| 2.3.2 | 扫描成功但结果为空，且之前缓存里有 Skill（疑似仓库被清空） | **空仓库防护**：报错并显示警告卡片，不清理任何引用与链接；缓存与链接保留 | `preload/api.js:refreshInternal` 空仓库分支 | 清空测试仓库后刷新 |
| 2.3.3 | 点击"确认仓库已清空" | 按"仓库确实为空"收敛：清理分组引用、启用记录与所有指向仓库的链接；仓库文件不动；卡片消失 | `src/views/SkillsView.vue:confirmEmptyRepository` → `refresh({allowEmptyRepository:true})` | 接 2.3.2 点击确认 |
| 2.3.4 | 扫描不完整（有坏目录/坏 SKILL.md） | 保持上次完整扫描的状态：**不更新缓存、不清理引用、不同步链接**；列表显示上次成功扫描的结果（从未成功扫描过则为空）；提示"本次扫描未完全成功..." | `preload/api.js:refreshInternal` 的 `!scan.complete` 分支 | 按 2.2.4 制造坏文件后刷新，确认已有链接与启用记录完全未变动 |
| 2.3.5 | 仓库中某个 Skill 被删除 | 刷新后：列表中消失；分组与启用记录中的引用自动清理并提示；其链接被删除 | `preload/api.js:refreshInternal` 引用清理 + `links.js:syncAgentLinks` | 删一个 skill 目录后刷新 |
| 2.3.6 | 仓库中某个 Skill 的 SKILL.md 改了 name | 列表显示新名字；id 与链接不受影响（无需重建） | `preload/scanner.js` + 同步保留条件 | 改元数据 name 后刷新 |
| 2.3.7 | 仓库中某个 Skill 目录改名 | 旧 id 消失（引用被清理），新 id 出现需用户重新勾选；旧链接因指向已不存在的路径（悬空）被清理 | 同上 | 重命名 skill 目录后刷新 |
| 2.3.8 | 仓库新增 Skill | 刷新后出现在列表，可勾选 | 同上 | 新建目录后刷新 |
| 2.3.9 | 切换仓库到另一个目录 | 先清理旧仓库在各 Agent 目录中的链接；旧引用（新仓库中不存在）被清理并提示；扫描并同步新仓库 | `preload/api.js:setRepository` | 准备两个仓库来回切换 |
| 2.3.10 | 重复扫描同一仓库 | 幂等：不产生多余链接、不重复提示 | 全部同步逻辑 | 连续点"重新扫描" |
| 2.3.11 | 仓库路径被移动 / 所在磁盘未挂载 | 报错提示；若本次无法确认任何结果，保留上次缓存列表 | `preload/scanner.js` + `refreshInternal` | 改仓库目录名后刷新 |
| 2.3.12 | 仓库目录含中文、空格 | 正常工作 | 全链路 | 用中文目录名测试 |

## 八、安全红线（修改代码时不可破坏）

1. **绝不修改/删除仓库源文件**：插件对统一 Skills 仓库只读（仅 `readdir`/`stat`/`readFile`），任何写操作都只发生在 Agent 目录与本地配置文件。见 `preload/scanner.js`、`preload/links.js`。
2. **删除范围（双模式安全边界）**：
   - **链接形式**：只删除「符号链接」且「目标在当前仓库内」（含路径在仓库内但已悬空的）。普通文件、普通目录、指向仓库外的链接（无论是否悬空）永不删除；仓库路径为空时不得删除任何链接。见 `links.js:isManagedLink`、`syncAgentLinks`、`removeManagedLinks`。
   - **直接复制**：只删除 `copiedSkills` 中有本插件复制记录、且删除前通过「真实目录 + 顶层存在 `SKILL.md` + 无内部符号链接 + 目录树指纹匹配复制快照或当前源 Skill」双重校验的目录；未记录的目录或任何校验不通过的内容一律保留并警告。见 `copies.js:verifyManagedCopy`、`syncAgentCopies`、`removeManagedCopies`。
3. **不清理的执行条件**：`scan.complete === false`（扫描不完整）或空仓库防护触发（`emptyRepository=true` 且未确认）时，不得删除任何链接或副本、不得清理任何引用。见 `api.js:refreshInternal`。
4. **不覆盖**：创建链接或复制副本时目标位置已有内容（链接/文件/目录）一律保留并提示，绝不覆盖；直接复制模式遇到同名冲突还必须按单 Skill 粒度回退启用状态。见 `links.js`、`copies.js`。
5. **路径比较统一入口**：必须使用 `preload/utils.js` 的 `comparablePath` / `pathsEqualLexical` / `isInsideDirectoryLexical`，禁止裸字符串比较（Windows 大小写、`\\?\` 前缀、分隔符差异会导致误判）。
6. **Agent 目录约束**：必须存在、可读、不能与仓库或已有 Agent 目录重合；目录中允许存在其他内容，插件仅管理自身受管的链接或副本；创建后名称、目录与配置方式均不可修改（无编辑入口，服务端无 update 方法）。
7. **配置文件原子写**：`preload/config.js:write` 必须保持"临时文件 + fsync + rename"，不得直接覆盖写。
8. **凭据/路径不落日志**：不要在提示或日志中输出完整仓库内容；错误提示仅包含路径与系统错误信息。

## 九、已知取舍与局限（不要当成 bug）

| # | 局限 | 说明 |
|---|---|---|
| 9.1 | 多窗口并发 | 仅保证单进程内写操作串行；两个窗口同时写时以最后写入为准，可能丢失另一个窗口的改动 |
| 9.2 | 配置损坏后无法清理链接 | 配置损坏被重置后，Agent 记录丢失，无法识别旧链接；重新配置后仅「指向当前仓库」的链接会随扫描收敛，其余需手动清理（见 9.8） |
| 9.3 | 300ms 防抖窗口 | 点击后立刻结束 uTools 进程（非隐藏）时，最近一次未提交的点击可能丢失（无持久化意图日志，这是刻意精简） |
| 9.4 | 嵌套 Skill 不支持 | 只扫描仓库第一层子目录；两层及以上结构不会被识别 |
| 9.5 | 不做完整性校验（哈希/大小） | 链接是否有效只看"目标路径是否匹配 + 是否悬空"，不校验源目录内容 |
| 9.6 | 手动改 Agent 目录路径后旧链接残留 | 手工编辑 state.json 绕过校验的行为不在保护范围，旧目录链接需手动清理 |
| 9.7 | 扫描期间无进度条 | 大目录扫描时界面显示"处理中"顶部进度条，但不显示具体进度 |
| 9.8 | 指向已删除旧仓库的悬空链接不再自动清理 | 为保证只清理「目标在当前仓库内」的链接，配置丢失或手工改路径后遗留的孤立悬空链接会被保留；启用同名 Skill 时提示"目标位置已被其他链接占用"，需手动清理 |
